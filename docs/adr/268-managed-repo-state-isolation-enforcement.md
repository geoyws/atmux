## Context

**The design is settled; this ADR is only about enforcement.** ADR-239 §Supplement-2026-05-26 and ADR-244 §Supersession-2026-05-26 decided, on the operator's verbatim instruction ("we best not let the other teams see that we're using atmux at all"), that every atmux artifact lives in the operator's personal dotfile tree at `~/work/journals/.sb/_dotfiles/atmux/<repo-key>/` and is **symlinked** into each managed repo's `.atmux/`, with the managed repo ignoring all of `.atmux/` and no `!.atmux/team.json` carve-out. Nothing below re-decides that. ADR-244 §S3 already promises the exact outcome the 2026-08-06 ask restates: *"No commit noise in product repos. Reviewers in sopx/unum/rentx never see atmux changes drifting through PRs."*

**The gap: that promise is carried by a 4-step operator recipe and zero lines of code.** ADR-239 §Supplement, "Bootstrapping a new managed repo", is four manual steps — create the dotfiles subdir, `ln -s`, confirm `.gitignore`, `atmux start`. Verified 2026-08-06 against the tree:

- `rg -l -i 'gitignore' src/ scripts/ templates/` returns exactly one file — `scripts/autopromote.sh`. No verb, no probe, no template reads or writes a `.gitignore`.
- `src/verbs/init.ts` scaffolds `.atmux/{inboxes,logs,state,archive}` (`init.ts:290-293`), writes a **real** `.atmux/team.json` from `templates/team.example.json` (`init.ts:347`), seeds `kanban.json` + `driver-inbox.md` + per-member inbox JSONs (`init.ts:358-381`), and installs the skills plugin (`init.ts:406`). It never touches any ignore file, never creates a dotfiles subdir, and never creates a symlink. (It also does not upsert `~/.claude/teams/registry.json` — `init.ts:50-56` and `init.ts:383-384` record that as a deferred port, which is why D3 does **not** use that registry as its enumeration source; see D3.)

So on every new managed repo, cleanliness rests on the operator remembering. **One forgotten ignore line commits atmux state into a product repo — the exact leak the 2026-08-06 ask forbids**, and George's teammates cloning `property-root` / `crm-react` / `tx-root` would then read his roster, orchestration config, and (once `state.db` or `decisions.md` land in-tree) his todo and plan artifacts.

**This is not hypothetical. Fleet audit, 2026-08-06, across the 13 `type: "team"` roots in `~/.atmux/cockpit.json`** (all 13 are git repos, all 13 have `.atmux/` present):

| Symptom | Count | Repos |

| atmux state **already committed and pushed** | 1 of 13 | `/root/work/ifca/src/tx-root` |
| `.atmux/team.json` is a real file, not a symlink | 12 of 13 | every root except `/root/work/ifca/src/rentx-root` |

## Decision

### D1 — `atmux init` establishes isolation idempotently, or refuses

`atmux init` — and therefore bare `atmux`, which aliases to `up` (`src/cli.ts:351`) and whose wizard gate calls `init` for a repo with no `team.json` (`src/verbs/up.ts:290`, per ADR-006's bring-up chain — note that call passes `--wizard`, which is still a stub per `src/verbs/up.ts:14-16`, so the isolation step must also be reachable from a plain `atmux init`) — gains an **isolation step** that runs before the `.atmux/` scaffold and is safe to re-run. It mirrors the `installSkillsPlugin` shape from ADR-217 §D5: probe → act only if wrong → report what it did.

**`atmux init` is not the only creator of a `.atmux/`, and the other one is deliberately OUT of scope.** `src/verbs/team/spawn-epic.ts:669-675` independently `mkdir`s `join(epicRoot, ".atmux")`, writes `.atmux/team.json` into it, then `openDb(join(childAtmuxDir, "state.db"))` — two of D1b's three durable entries, created with no `init` call, no manifest row, and no symlink. **Epic cages are out of scope for D1 and D3**, for two reasons that hold on inspection: (a) an epic cage's root lives under `<parentProjectRoot>-epics/<epicId>/`, outside the managed product repo's worktree, so nothing it writes can be staged by the product repo's index — the leak class D2 asserts against is structurally absent; (b) epic cages are ephemeral and dissolve ([ADR-090](090-epic-team-lifecycle.md); the `<projectRoot>-epics/<epicId>/` residency is documented at `src/schema/team.ts:963`), so a durable-symlink guarantee has nothing to protect. Evidence that they nonetheless accumulate operator-side state: `~/work/journals/.sb/_dotfiles/atmux/` carries three epic-cage keys placed there by hand — `e-21-6593dd0f/`, `e-22-4d6af038/`, `e-23-0f71512b/`, each with a `team.json` whose `.name` equals the key. D3's manifest bootstrap records those keys as-is (D1a) and its repo sweep skips them, because they are not repo roots. If a future decision wants epic cages isolated too, that is its own ADR — this one does not silently claim the coverage.

**D1a — `<repo-key>` derivation, deterministic and collision-checked.**
`<repo-key>` = the **basename of the repo root directory**, when that basename is *admissible*. Inadmissible: empty, `.`, `..`, any name beginning with `.`, and the reserved-ambiguous set `{root, src, repo, project, main}`. On an inadmissible basename `atmux init` **refuses** and requires `--state-key <key>`; it never invents a disambiguating suffix.

**Census of the live dotfiles tree, re-derived 2026-08-06** (`ls -d ~/work/journals/.sb/_dotfiles/atmux/*/` → **26** subdirectories; then a `team.json` existence test per directory):

- **6 are tool infrastructure, not state keys** — `archive/`, `bin/`, `crontab-backups/`, `extensions/`, `logs/`, `state/`. None carries a `team.json`.
- **20 carry a `team.json` and are therefore `<repo-key>` state directories.** That 20 is the denominator, and it is the number D3's manifest bootstrap must seed.

Of those 20, basename derivation would be correct for **8**: `atmux`, `aix-root`, `mx-root`, `rentx-root`, `sopx-root`, `ix-root`, `ifca-docs`, `auditx-root`. (`sopx-root` is an orphan key: `/root/work/ifca/src/sopx-root` is now a bare directory containing only `.atmux/` with no `.git` — the repo it keyed is gone from disk.) The other **12 are not repo-root basenames**, and they split three ways:

| Shape | Keys | Why basename fails |
|---|---|---|
| Repo root whose basename is inadmissible | `unum-root` (→ `/root/work/unum/src/root`), `journal` (→ `/root/work/journals/.sb`) | basename would be `root` (reserved) and `.sb` (dot-leading) — exactly the two inadmissible classes above, which is what forces the `--state-key` refusal branch rather than a heuristic |
| Team-name / branch / tier-shaped (7 keys) | `rentx` and `rentx-geoyws-staging-rentx-root` (both `.name` `rentx`); `sopx-staging`, `sopx-geoyws-e2e`, `sopx-geoyws-driver-2-staging`, `sopx-geoyws-driver-3-baseline-fixloop-e2e`, `sopx-geoyws-header-ifcax-layout-staging` (all five `.name` `sopx`, verified 2026-08-06) | these were keyed by team name or by branch/tier, not by repo root, before any convention existed |
| Epic-cage keys | `e-21-6593dd0f`, `e-22-4d6af038`, `e-23-0f71512b` | not repo roots at all — out of scope per D1 above |

So basename is correct for **8 of the 20** live keys, not a large majority. That is the load-bearing point: the manifest and the refusal branch are the mechanism, and basename derivation is only the convenient default for new repos.

**None of the 20 `team.json` files carries a repo path.** Verified 2026-08-06: `rg -q 'repoPath'` across all 20 returns zero hits, and `repoPath` is in any case an optional field of the `gitter` sub-block only (`src/schema/team.ts:571-581`), not a project-root field. Consequence for D3: the dotfiles tree can enumerate **keys**, but it cannot yield **repo roots** — which is why D3 needs two enumeration sources, not one (see D3).

**D1a-manifest — two collision directions, both live.**
Collisions are detected against a **manifest** at `~/.atmux/state-keys.json` — which lives inside the dotfiles tree by virtue of the existing `~/.atmux` symlink (verified: `/root/.atmux -> /root/work/journals/.sb/_dotfiles/atmux`), so it is snapshotted by `dotfiles push` for free. Shape: a flat `{ "<repo-key>": "<absolute repo root>" }` map.

1. **One key → two paths.** `atmux init` **refuses** when the key is present and maps to a different absolute path, printing both paths and the `--state-key` remedy. When the key is present and maps to this repo, the step is a no-op.
2. **Two keys → one path.** A flat key-addressed map cannot express this, so D1a additionally requires the manifest's **values to be unique**, and `atmux init` refuses when the resolved repo root is already claimed under a *different* key. **This is live today, not hypothetical**: three dotfiles keys all describe the single repo root `/root/work/ifca/src/rentx-root` — `rentx/team.json` (`.name` `rentx`, mtime 2026-06-12, 5409 bytes), `rentx-root/team.json` (`.name` `rx`, mtime 2026-08-03, 2573 bytes), and `rentx-geoyws-staging-rentx-root/team.json` (`.name` `rentx`). The live symlink `/root/work/ifca/src/rentx-root/.atmux/team.json` resolves to `~/work/journals/.sb/_dotfiles/atmux/rentx-root/team.json`, so `rentx-root` is the winner and the other two are historical residue.

**Bootstrap must therefore not refuse on its own first run.** D3's manifest bootstrap records all 20 existing keys **as-is** — `unum-root`, `journal`, the `sopx`/`rentx` branch-shaped keys, the three epic-cage keys, all of them — and **nothing already on disk is renamed**. For a repo with more than one candidate key (the `rentx-root` trio), the bootstrap seeds the mapping from the **resolved symlink target of the repo's live `.atmux/team.json`** when one exists, and records the others as `unmapped` rows carrying no repo path. Only *subsequent* `atmux init` runs, and D3 `--apply` on a repo whose mapping is genuinely ambiguous, hit the refusal branches. Refusing on the bootstrap itself would make the fleet permanently unfixable.

**D1b — symlink granularity: per-entry, over a frozen durable set. `.atmux/` itself stays a real directory.**
This resolves the ambiguity ADR-239 §Supplement left open ("Out-of-scope for this supplement: kanban.sqlite + decisions.md storage") in the direction ADR-244 §S1's own tree diagram already pointed.

- **Symlinked into `~/work/journals/.sb/_dotfiles/atmux/<repo-key>/`** — exactly three entries: `team.json`, `decisions.md`, `state.db`. Roster (ADR-239 §A2), decision log (ADR-008), kanban (ADR-126). These are the artifacts whose loss is unrecoverable and whose leak is the operator's stated concern.
- **NOT symlinked — stays a local real path** — everything else, specifically `worktrees/`, `logs/`, `archive/`, `sockets/`, `inboxes/`, `heartbeats/`, every `*.lock` sidecar, and the high-churn append logs `driver-inbox.md` / `lead-outbox.md`.

**`.atmux/` as a whole must NOT be the symlink.** Measured in `/root/work/src/atmux/.atmux` on 2026-08-06: `worktrees/` is 144 MB and `logs/` is 184 MB. Making `.atmux/` a symlink into the dotfiles tree would place full product-repo git worktrees (ADR-082 / ADR-084 / ADR-239 §A1) *inside the dotfiles git repo* — nested checkouts that `dotfiles push` would then try to commit — and would push ~330 MB of churn per team into the snapshot path. Lock files are machine-local mutexes and must not be shared across machines through a synced tree. The three-entry set is the smallest that satisfies durability without any of that.

**D1c — the four situations, with exact behaviour.**

| Situation | Behaviour |
|---|---|
| Ignore pattern already present (any of the three live shapes) | no-op, report `already isolated` |
| `.atmux/` exists as a real directory (the current state of 13 of 13 roots — verified 2026-08-06: no root has `.atmux` as a symlink) | keep the directory; convert **only** the three D1b entries. For each: if already a correct symlink → no-op; if absent → create the dotfiles target then symlink; if a **real file** → move the file into the dotfiles path, then symlink (never delete, never silently overwrite). When both a real in-repo file and a dotfiles file exist and differ — the verified atmux-team `team.json` case — **refuse** and print both paths, mtimes, and a `diff` hint. An automated pick would silently discard the roster edits made between 2026-06-12 and 2026-07-28. This branch is compatibility surface: sunset it per ADR-266 once D3 reports the fleet clean. |
| `.atmux/` is already a symlink (whole-directory form, from a hand-rolled `ln -s`) | **refuse** with a message naming the D1b decision. Do not rewrite the operator's link. |
| Dotfiles tree absent — `~/work/journals/.sb/_dotfiles/atmux/` does not exist (a non-operator machine, a CI runner, a fresh box before `dotfiles pull`) | **fail closed.** Refuse the isolation step with `ConfigError` → exit 78 per ADR-006's sysexit mapping (`src/cli.ts`), naming the missing path and `dotfiles pull` as the remedy. **Never fall back to writing state into the repo** — a silent fallback is the leak this ADR exists to prevent. `--no-isolate` is the explicit, documented opt-out for anyone running atmux without the operator's dotfiles; it must print a one-line warning that state will be repo-local and is not covered by any snapshot. |

**D1d — where the ignore pattern is written: the machine-global excludes file, not the product repo's tracked `.gitignore`.**
This is a deliberate deviation from ADR-239 §Supplement step 3 ("Confirm `.gitignore` excludes `.atmux/*`"), because that step, applied to a product repo, **is itself the disclosure it is meant to prevent**: a `.atmux/` line in a tracked `.gitignore` is a committed, teammate-visible statement that the operator runs atmux — which contradicts the ADR-244 §Supersession driver-ref verbatim. Three candidate mechanisms, all tested on this box on 2026-08-06:

1. **Machine-global `${XDG_CONFIG_HOME:-$HOME/.config}/git/ignore`** — **CHOSEN.** Verified 2026-08-06, with the confounders eliminated: the sole pattern in that file, `/root/.config/git/ignore:1` = `**/.claude/settings.local.json`, appears in neither `/root/work/src/atmux/.gitignore` nor `/root/work/src/atmux/.git/info/exclude`, and `git check-ignore -v -- .claude/settings.local.json` run from inside the linked worktree `/root/work/src/atmux/.atmux/worktrees/driver-2` exits **0** citing `/root/.config/git/ignore:1`. So the global file reaches linked worktrees, and the match is attributable to it alone. One file, every repo, every worktree, zero product-repo commits, invisible to teammates. Patterns written (idempotent, append-if-absent, each on its own line with a leading comment citing this ADR): `**/.atmux/` plus the D4 set.
2. **Per-repo `.git/info/exclude`** — **REJECTED, but not for the reason first recorded.** An earlier draft of this ADR claimed `.git/info/exclude` does **not** propagate to linked worktrees, citing `git check-ignore .claude/worktrees` from `/root/work/src/atmux/.atmux/worktrees/driver-2` reporting NOT-IGNORED. **That measurement was wrong, and it was wrong for the same reason the bare-`.atmux` assertion in §Context is wrong: a path-shape mismatch, not a propagation failure.** `**/.claude/worktrees/` is a directory-only pattern (trailing slash) and `.claude/worktrees` does not exist as a directory inside `driver-2`, so the slash-less probe path could not match. Re-verified 2026-08-06 on git 2.43.0 with a pattern that lives **only** in `.git/info/exclude` (`**/.claude/agent-registry.json`, at `/root/work/src/atmux/.git/info/exclude:14`, absent from both the tracked `.gitignore` and `/root/.config/git/ignore`): from `/root/work/src/atmux/.atmux/worktrees/driver-2`, `git check-ignore -v -- .claude/agent-registry.json` exits **0** and cites `/root/work/src/atmux/.git/info/exclude:14`. And `git check-ignore -v -- .claude/worktrees/` (with the trailing slash) matches from `driver-2` too. **`info/exclude` resolves from `$GIT_COMMON_DIR`, so it does propagate to linked worktrees** — ADR-239 §A1's five driver worktrees are covered by it.

  The real rejection grounds are two, and neither is about worktrees: (a) it is **per-repo**, so the guarantee must be re-established by hand in every managed repo and is silently lost on any fresh `git clone` — the same "rests on the operator remembering" failure this ADR exists to remove; (b) `.git/` is **not** snapshotted by `dotfiles push`, so the guarantee dies with the box, whereas mechanism 1 relocated into the dotfiles tree survives. Mechanism 1 is chosen on those grounds, on the strength of its own verified match from inside `driver-2` — **not** on a defect in mechanism 2 that does not exist. The corrected measurement is recorded here rather than deleted, because a rejected-alternative rationale that a reader cannot reproduce is worse than no rationale.
3. **Product repo's tracked `.gitignore`** — **used only for atmux's own repo**, where atmux *is* the product and the stanza is documentation rather than a tell, and elsewhere only behind an explicit `--track-gitignore` flag. The `.atmux` ignore lines already committed in the other **7** roots that carry one — `/root/work/unum/src/root`, `/root/work/ifca/src/mx-root`, `/root/work/ifca/src/rentx-root`, `/root/work/ifca/src/ifca-docs`, `/root/work/journals/.sb`, `/root/work/ifca/src/aix-root`, `/root/work/ifca/src/crm-react` (line numbers in §Context) — are **left alone**: they are already public, they are harmless, and removing them would be a second disclosing commit for no gain.

Because the global excludes file is the load-bearing mechanism, D1 also **relocates it into the dotfiles tree**, so that `dotfiles push` snapshots it and a fresh machine restores it during dotfile bootstrap. Verified 2026-08-06: `/root/.config/git/ignore` is a plain local file (31 bytes, one pattern), not a symlink, and not tracked in the dotfiles repo — so today the whole guarantee would be lost with the box.

**The bootstrap question is answered, not open.** Verified 2026-08-06 in `~/work/journals/.sb/_dotfiles` (a git submodule of `~/work/journals/.sb`): the directory `_dotfiles/git/` exists and is tracked, containing exactly one file, `git/.gitconfig`. There is **no** `git/ignore` in it. The bootstrap does have a symlink mechanism and it does deploy that directory — `init.sh:154` runs `link_file "$DOTFILES_DIR/git/.gitconfig" "$HOME/.gitconfig"`, mirrored by `ansible/roles/dotfiles/defaults/main.yml:24-25` (`src: git/.gitconfig` → `dest: ~/.gitconfig`) — and `/root/.gitconfig` is indeed already a symlink to `/root/work/journals/.sb/_dotfiles/git/.gitconfig`. But there is **no entry for `git/ignore`**, so the relocation needs one dotfiles-side change, which the operator owns.

Two forms are available, and **form (b) is preferred because it adds no new plumbing**:

- **(a) Symlink form.** Add `git/ignore` to `_dotfiles/`, then link `${XDG_CONFIG_HOME:-$HOME/.config}/git/ignore` → `~/work/journals/.sb/_dotfiles/git/ignore` — the same pattern `~/.atmux` and `~/.gitconfig` already use. Cost: a new file plus a new `init.sh` / ansible link entry.
- **(b) `core.excludesFile` form.** Add `git/ignore` to `_dotfiles/` and set `core.excludesFile = /root/work/journals/.sb/_dotfiles/git/ignore` in the **already-tracked, already-symlinked** `_dotfiles/git/.gitconfig`. Verified 2026-08-06: that file sets no `core.excludesFile` today (`git config --global --get core.excludesFile` → exit 1), which is why git falls back to the `${XDG_CONFIG_HOME}/git/ignore` default. Cost: one config line in a file the bootstrap already deploys — **zero new symlinks, zero new bootstrap entries**, and it travels to every machine that runs `dotfiles pull`.

Either way this is a change inside the operator's dotfiles repo, not inside atmux. Until it lands, D1 must **warn** that the excludes file is not snapshotted rather than silently depend on it — the isolation guarantee still holds on this box, only the machine-death recovery leg is missing.

### D2 — Doctor probe `managed-repo-state-untracked`

A new probe in `src/verbs/doctor/git.ts`, registered in `src/verbs/doctor.ts` alongside its nearest sibling `checkWorktreeNestedStateDb` (`doctor.ts:243`; probe body at `git.ts:412-438`, whose row shape — `{status, label, detail, hint}` from `src/verbs/doctor/types.ts:8-13` — this one mirrors verbatim). Signature follows the sibling: `checkManagedRepoStateUntracked(team: Team | null, atmuxDir: string, opts): Promise<DoctorRow[]>`, with a `GitSpawn` injection point (`types.ts:37-40`) so tests never shell out.

**Two assertions, both required:**

1. **Ignored.** `git check-ignore -q -- .atmux/team.json` exits 0. The probe asserts on the **concrete child path**, never on the bare directory name `.atmux` — verified above, `.atmux/*` does not match `.atmux`, so a bare-path assertion would emit false reds on the **5 roots** using the `.atmux/*` form (`/root/work/src/atmux`, `/root/work/unum/src/root`, `/root/work/ifca/src/mx-root`, `/root/work/ifca/src/rentx-root`, `/root/work/ifca/src/ifca-docs`) — 5 false reds against 5 true reds, i.e. a probe that is wrong half the time it fires. For completeness the probe checks all three D1b entries (`team.json`, `decisions.md`, `state.db`) and reports the first failure. **Every `check-ignore` invocation in this ADR, in D3, and in any implementation of them uses the `-q -- <child-path>` form**; the bare-directory form is forbidden, and a test must pin that (a fixture repo whose only pattern is `.atmux/*`, asserting the probe returns green).
2. **Untracked.** `git ls-files -- .atmux` returns empty. This is the assertion that catches state committed **before** any ignore pattern landed: **gitignore has no effect on already-tracked paths**, so assertion 1 can pass while the artifact sits in history forever. This is live today on `/root/work/ifca/src/tx-root`, whose `.atmux/team.json` is tracked and reachable in `origin/tx-geoyws`. Remediation in the row's `hint`: `git rm -r --cached .atmux`, then commit — the file stays on disk, and **history is not rewritten**. Rewriting the pushed IFCA-org branch is a separate act requiring explicit operator authorization under the push policy; neither the probe nor D3 proposes it.

**Severity and gating.** Assertion-2 failure (tracked state) is **red** — it is an active disclosure. Assertion-1 failure (not ignored, nothing tracked yet) is also **red**: it is one `git add .` away from becoming assertion 2, and 5 of 13 roots are in that state right now. A missing/incorrect symlink for a D1b entry (state is isolated but not durable) is **yellow** — the leak is closed, the snapshot is not. Non-git cwd, or `team === null`, returns no rows (silent skip, exactly as `checkSubmoduleIntegrity` at `git.ts:73` and `checkWorktreeNestedStateDb` at `git.ts:417` do).

**What red actually blocks, precisely** — the honest answer is "one entry point, not the other":
- **Bare `atmux` / `atmux up` is blocked.** `src/verbs/up.ts:218-231` runs `doctor --quiet` and, on non-zero rc, re-runs doctor verbosely and throws `ConfigError("preflight failed")` **before** the start step. `atmux doctor` returns 1 whenever `redCount > 0` (`src/verbs/doctor.ts:378`). So a red isolation row stops the ADR-006 bring-up path.
- **Explicit `atmux start` is NOT blocked.** `src/verbs/start.ts:373-376` parses `--doctor` / `--no-doctor` for arg-shape parity but logs `doctor mode … preflight body deferred to Phase 2` and runs no probes. This ADR does **not** wire that body — doing so changes the behaviour of every existing team's start path and belongs to its own decision. The consequence is stated plainly rather than papered over: an operator who always types `atmux start` will not see the probe until they run `atmux doctor` or D3's sweep.

### D3 — Fleet sweep for the repos already managed

New subverb `atmux doctor --sweep-isolation` (read-only by default, `--apply` to fix), because the check is already a doctor probe and a second top-level verb would be ceremony.

**Two enumeration sources, because they answer two different questions, and neither is the Claude teams registry.** The sweep needs *repo roots* to run `git` in, and *state keys* to build the manifest from; no single file on disk carries both.

| Question | Source | Verified yield, 2026-08-06 |
|---|---|---|
| **Which repos do I sweep?** (run `check-ignore` / `ls-files` in) | `~/.atmux/cockpit.json` → `sessions[]` where `type === "team"` → `.root` | **13** roots, all git repos, all with `.atmux/` present |
| **Which `<repo-key>`s must the manifest seed?** | the dotfiles tree — `~/work/journals/.sb/_dotfiles/atmux/*/`, keeping directories that contain a `team.json` | **20** keys out of 26 subdirectories (D1a's census) |

The two sets overlap but neither contains the other. `journal` and `unum-root` are keys whose repo roots *are* in the cockpit under different names; `sopx-root`, `auditx-root`, the seven `sopx`/`rentx` branch- and tier-shaped keys and the three epic-cage keys — 12 keys in total — have **no** cockpit session of their own, so a cockpit-only sweep never opens their state directories; and `/root/work/ifca/src/crm-react`, `/root/work/ifca/src/hotel-service`, `/root/work/ifca/src/tx-root`, `/root/work/src/opencode-plugin-orch`, `/root/work/hig` are cockpit roots with **no** dotfiles key, so a dotfiles-only sweep never sees the realized `tx-root` leak. Sweeping the union is what makes the report complete. Because the 20 `team.json` files carry no repo path (D1a, verified), dotfiles-only keys are reported as **key rows** — key, presence of each durable entry, no ignore verdict — not as repo rows; `--root <path>` audits one repo outside the cockpit. `medic` and any `root: null` session are skipped.

**Explicitly NOT `~/.claude/teams/registry.json` — it cannot be an enumeration source, and this ADR must not be read as depending on it.** Verified 2026-08-06: the file is a JSON **array** of **2** entries — `sopx` → `/root/work/ifca/src/sopx-root` and `atmux` → `/root/work/src/atmux`, both `lastSeen: 1778198714`, both `status: "running"`. It is stale by construction, not by accident: **`src/verbs/init.ts` never upserts it.** `init.ts:50-56` records the registry abstraction as "not yet ported in atmux-bun … Phase 2/5 follow-up wires this in", and `init.ts:383-384` is the corresponding skipped call site ("Skipped per header comment: bash :70-77 atmux::registry_upsert"). Nothing else in the TS codebase writes it. Two consequences, stated so no implementer re-anchors on it by accident: (a) using it would audit 2 of 13 repos and report the fleet green, and its `sopx` entry points at `/root/work/ifca/src/sopx-root`, which is no longer a git repo at all — a second independent falsehood in a 2-row file; (b) making the registry a viable *third* source is a **future improvement gated on that unported upsert landing**, not a dependency of this ADR. If and when `atmux init` upserts the registry, D3 may add it as a cross-check; until then D3 must not read it.

**In scope, repo side (13 cockpit roots)** — the IFCA tree (`/root/work/ifca/src/{aix-root,mx-root,crm-react,hotel-service,rentx-root,tx-root,ix-root,ifca-docs}`), the Unum tree (`/root/work/unum/src/root`), and the personal roots (`/root/work/src/atmux`, `/root/work/journals/.sb`, `/root/work/src/opencode-plugin-orch`, `/root/work/hig`).

**In scope, key side (20 dotfiles keys)** — every directory under `~/work/journals/.sb/_dotfiles/atmux/` that holds a `team.json`, enumerated in D1a. The 6 tool-infrastructure directories (`archive/`, `bin/`, `crontab-backups/`, `extensions/`, `logs/`, `state/`) are skipped by the `team.json` test, so the sweep needs no hardcoded deny-list.

**Output**: one row per repo — repo path, resolved `<repo-key>`, ignore verdict, tracked-count, per-entry symlink verdict — plus one key row per dotfiles-only key, plus `--json` for scripting.

**`--apply` performs exactly D1's actions and inherits every one of its refusals.** Its whole action vocabulary is: create a dotfiles target directory, move a real file into it and symlink back, append a pattern to the global excludes file, write a manifest row. Explicitly, `--apply`:

- **never deletes any file or directory, under any flag.** There is no delete verb in the sweep. In particular it never proposes removing a `<repo-key>` state directory under `~/work/journals/.sb/_dotfiles/atmux/` — those hold the operator's live `decisions.md` and `team.json` (see §Open questions 4).
- never resolves a diverged real-file-vs-dotfiles pair (the atmux `team.json` case) — it refuses and prints both paths;
- never rewrites a tracked `.gitignore` without `--track-gitignore`;
- never runs `git rm -r --cached` on the operator's behalf — that one prints the command and stops, because it is a commit in a product repo and the operator's push policy governs commits;
- never rewrites published git history, and never force-pushes. Remediating `tx-root`'s already-pushed blob past step 1 requires explicit operator authorization.

### D4 — The `.claude/` sibling: enumerate the private artifacts, protect the shared ones

The same global excludes file carries the `.claude/` private set, so agent artifacts of **both** kinds stay out of the product repo. This is deliberately an **enumeration, not a blanket `.claude/`** — that distinction is load-bearing.

- **Ignored (operator-private, per-machine, or per-session)**: `**/.claude/team.json` (the ADR-164 materialization of the private roster), `**/.claude/settings.local.json` (already at `/root/.config/git/ignore:1`), `**/.claude/scheduled_tasks.lock`, `**/.claude/worktrees/`, `**/.claude/projects/`. atmux's own `.git/info/exclude` already lists a superset of the Claude-harness private files (`scheduled_tasks.json`, `routines/.state/`, `checkpoints/`, `mailbox/`, `agent-registry.json`, `agent-memory-local`, `first-run`, `assistant-daemon-state.json`); D1d promotes that set from a per-repo file — which does reach linked worktrees, but is per-repo and outside `dotfiles push` (see D1d mechanism 2) — to the global one.
- **Left tracked (shared team assets teammates SHOULD see)**: `CLAUDE.md`, `.claude/skills/**`, `.claude/agents/**`, `.claude/commands/**`, and a project's committed `.claude/settings.json` where the project intends one. Verified: atmux tracks exactly 4 files under `.claude/` — `.claude/skills/{rcheckout,rpull,rpush,rreset}/SKILL.md` — the recursive-ops skills of ADR-035, which are *documentation of a shared contract*, not private artifacts. A blanket `**/.claude/` pattern would hide them.
- **The overreach already exists and is named, not propagated**: `/root/work/ifca/src/crm-react/.gitignore:5` is a bare `.claude/`, and that repo tracks 0 files under `.claude/` — so any future shared skill added there is invisible by default. D3 reports this as **yellow (over-broad)** with the enumerated replacement in the hint. It does not auto-edit a tracked `.gitignore`; narrowing an ignore is a judgment call about what teammates should see, and that is the operator's.
- **Note on `**/.claude/settings.json`**: atmux's own tracked `.gitignore:11` ignores it, which is right for atmux (the operator's local harness config) and would be wrong for a project that ships a committed team settings file. The global set therefore **omits** `settings.json`; repos that want it private keep their existing local line.

## Consequences

**Positive**

- The R2 guarantee moves from operator memory to two code paths and one probe: `atmux init` establishes it, `atmux doctor` proves it, `--sweep-isolation` finds the repos where it was never established. ADR-244 §S3's "no commit noise in product repos" becomes checkable instead of aspirational.
- The 5 currently-unignored roots and the 1 realized leak (`tx-root`) are surfaced by a single command rather than by a teammate noticing.
- D1b's three-entry symlink set closes the divergence class the audit found (the atmux team's own `team.json`: in-repo mtime 2026-07-28 with 3 drivers against dotfiles mtime 2026-06-12 with 5, and `dotfiles push` snapshotting the stale copy). Once symlinked there is one file, so drift is structurally impossible.
- The chosen mechanism adds **zero commits to any product repo** in the default path — strictly better than ADR-239 §Supplement step 3, and the only variant consistent with "don't let the other teams see that we're using atmux at all."
- No new subsystem: one step inside an existing verb, one probe in an existing probe module, one subverb flag on an existing verb, one manifest file inside an already-dotfiles-resident directory.

**Negative / risks**

- **A global excludes file is a machine-wide side effect.** `atmux init` writing to `~/.config/git/ignore` affects every repo on the box, including repos atmux does not manage. Mitigated by narrow, `.atmux`/`.claude`-scoped patterns, append-if-absent idempotency, and an ADR-citing comment line; but it is a wider blast radius than a per-repo file, and per D1d it is the price of **one place to establish the guarantee and one place `dotfiles push` can snapshot** — not, as an earlier draft claimed, the price of surviving linked worktrees (`.git/info/exclude` survives those too; the corrected measurement is in D1d).
- **Recovery on a fresh machine is a two-step, and step one is manual.** `dotfiles pull` restores `~/work/journals/.sb/_dotfiles/atmux/<repo-key>/`; then `atmux init` in each managed repo re-creates the three symlinks idempotently. Until `dotfiles pull` has run, D1c's fail-closed branch refuses rather than scaffolding repo-local state — correct, but it means atmux is unusable on a fresh box until the dotfiles land. That ordering must be in the runbook. **Caveat, verified 2026-08-06**: the excludes-file leg of that recovery does **not** work yet — `_dotfiles/git/ignore` does not exist and the bootstrap has no entry for it (D1d), so a fresh box restores the state directories but not the ignore patterns. Until the operator lands D1d's form (a) or form (b), `atmux init` must re-append the patterns to the local excludes file on the new box and warn that they are not snapshotted.
- **`dotfiles push` remains the only snapshot cadence, and it is operator-driven (ADR-244 §S3).** An operator who never pushes dotfiles has **no backup at all** — the symlinks give a single source of truth, not durability. Nothing in this ADR adds a cadence; it deliberately does not resurrect ADR-244 §D1's pre-commit hook. The honest statement for the runbook: isolation protects teammates from your artifacts; only `dotfiles push` protects you from machine death.
- **Symlinking `state.db` puts a multi-megabyte, constantly-rewritten binary in the dotfiles repo** — 6,033,408 bytes (5.8 MiB) for atmux's own team, measured 2026-08-06 — so every `dotfiles push` after activity adds a full blob, and git cannot delta-compress a rewritten SQLite page file usefully. **Accepted for Phase 1 as the price of ADR-126 durability, with an explicit revisit trigger rather than an open-ended acceptance: revisit when either (a) `~/work/journals/.sb/_dotfiles/.git` exceeds 1 GB, or (b) a single `dotfiles push` exceeds 30 s wall-clock.** Whichever fires first, the successor is a JSON-dump-on-demand ADR (ADR-244 §D1's original instinct, minus the hook), not a reversal of this one. Both thresholds are measurable with `du -sh` and `time`, so the trigger is checkable rather than a judgment call.
- **SQLite WAL/SHM sidecars follow the resolved symlink target**, so `state.db-wal` / `state.db-shm` will materialize inside the dotfiles tree next to `state.db`. Verified 2026-08-06: `~/work/journals/.sb/_dotfiles/.gitignore` contains **no** `*-wal`, `*-shm`, or `*.db` pattern, and no `state.db` is tracked there yet — so today all three files would show up untracked and `dotfiles push` would offer to commit them. Adding `atmux/*/state.db-wal` + `atmux/*/state.db-shm` to that `.gitignore` is a Phase-1 deliverable. Separately, a `dotfiles push` taken mid-write snapshots a DB whose latest pages are only in the un-committed WAL; **untested — verify** whether a `PRAGMA wal_checkpoint(TRUNCATE)` before push is needed to make the snapshot self-consistent. Not a resolved point.
- **Explicit `atmux start` still does not run the probe** (`start.ts:373-376`, preflight body deferred). Only bare `atmux` / `atmux up` is gated (`up.ts:218-231`). Operators who type `atmux start` need `atmux doctor` or the sweep.
- **`tx-root`'s already-pushed leak is not fully remediable by this ADR, and the remaining half needs operator authorization.** Two-step: (1) `git rm -r --cached .atmux` in `/root/work/ifca/src/tx-root` + commit stops future tracking and leaves the file on disk — safe, local, and the only step D3 will print; (2) removing the blob from `origin/tx-geoyws` history on `git@github.com:ifca-software/tx-root.git` is a **history rewrite plus a force-push to an IFCA-org branch**, which is out of scope here and **must not be performed by any agent without explicit operator authorization under the push policy**. Until step 2, the topology disclosure stands in published history. Stated plainly rather than left implicit, so no future sweep treats it as routine cleanup.
- **D1c's real-file-to-symlink conversion is compatibility surface** for the 12 roots currently holding real files. It earns an ADR-266 sunset entry, retired once `--sweep-isolation` reports the fleet clean.

**Reversibility: HIGH.** Yanking this ADR = delete the isolation step from `init.ts`, delete the probe + its registration, delete the sweep flag, and (optionally) remove the appended lines from the global excludes file. The symlinks and the dotfiles subdirs are inert data that atmux's `fs` reads already traverse transparently (ADR-244 §S1) — nothing in the runtime depends on whether a path is a link. No schema change, no event-topic change, no migration.

- **Rewriting pushed history** in `tx-root` or anywhere else — and **deleting anything**: no verb, probe, or sweep path introduced by this ADR removes a file or directory, in a managed repo or in the dotfiles tree.
- **Wiring `atmux start`'s deferred doctor preflight body** (`start.ts:373-376`) — a behaviour change for every existing team; its own ADR.
- **Retro-narrowing the over-broad `.claude/` line in `crm-react`** — reported as yellow, never auto-edited (D4).
