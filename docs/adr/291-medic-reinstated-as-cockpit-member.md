## Context

**The paper retirement never reached the code, and its precondition no longer exists.** ADR-212 §D1 retired the medic cockpit role on 2026-05-21 and §D5 sequenced the cutover behind the Honker/orchd consumer substrate — "medic retires LAST after substrate ≥30 days observed-stable". [ADR-276](276-orchd-retirement-and-atmux-scope.md) deleted that substrate outright on 2026-08-27, so §D5's precondition can never be met. §D6's `medic-config-residue` doctor probe was never implemented — measured 2026-09-07, `src/verbs/doctor*.ts` contains no such probe. Meanwhile every live medic code path stayed in tree: `src/verbs/cockpit.ts` creates the `_medic` window on every reconcile when the roster's `type: "medic"` entry (or the top-level `medic` block) has `enabled: true`; `src/verbs/cockpit-rotate.ts` rotates role `medic`; `src/verbs/status.ts` probes it. kb attention `a-cce8a963` (2026-09-04) named the inconsistency — a role documented as retired, shipped as live — and asked the operator to decide. On 2026-09-07 the operator decided: keep the medic.

**The last shim sweep already declined to remove it.** [ADR-266](266-shim-sunset-policy-and-first-sweep.md) swept the expired ADR-133 `superdoctor` → `medic` shims (§D2) and listed, under §KEEP, "`_medic` window + config" as deliberately retained. So the most recent decision that actually touched this surface treated the medic window as live infrastructure while ADR-212 still read as its retirement notice. This ADR ends that split.

**The operator already runs the medic as a kb worker.** A `medic` kb board exists on `@@hax` (dotfiles `agents/skills/kb/hosts.tsv` row `medic`), lane `medic`, actors `claude@medic` / `codex@medic`. Rows worked there include `t-a9b264f0` "Diagnose and relieve HIG resource pressure", `t-be2b9f94` "Investigate renewed HIG disk pressure" and `t-583c43ed` "Make HIG BuildKit cache control durable" (all tagged `infra`); `t-df956834` — the ADR-290 `_superdriver` → `_sd` shortform work — was itself done by `claude@medic`. The role the operator wants is therefore not the 2026-05-08 hourly-tick role: it is a cockpit lane in the ADR-290 §D2 shape, working its own board under an operator-armed standing goal.

**Live cockpits, measured 2026-09-07.** `@@hax` session `atmux_cockpit` (socket `/tmp/tmux-0/atmux-cockpit`): `1:_superdriver 2:_medic` (running codex) `3:_misc 4:journal 5:px`. `@@mbp` session `atx` (socket `/tmp/tmux-501/atmux-cockpit`): `1:_superdriver 2:_sd2 3:_sd3 4:_misc 5:geoyws 6:unum 7:ifca` — **no `_medic`**, even though `~/.atmux/cockpit.macos.json` declares `{ "type": "medic", "name": "medic", "enabled": true, "autoStart": false, … }`.

**Why `@@mbp` has no `_medic`, stated only as far as the evidence goes.** Two `atmux cockpit reconcile --no-launch` runs on 2026-09-03 **exited 65**, per `~/.atmux/logs/2026/09/events.jsonl`. The refusal *source* was not captured and does not reproduce: exit 65 is `EX_DATAERR`, which in this tree is the `schema` error tag alone (`src/errors.ts:409-410`), and on 2026-09-07 the branch code parsed `loadCockpit` plus all 42 enabled `team.json` files without a schema error. Note also what exit 65 is **not**: `refusePlannedDestructiveOps` raises `UsageError` → exit **64** (`src/errors.ts:386`), and its dry-run planner cannot even model a move-with-kill for a fresh add (the `md === undefined` guard, `src/verbs/cockpit.ts:2554-2568`). The 2026-09-03 exits are therefore an unexplained data-shape refusal, not a destructive-op gate firing.

**The slot hazard was real and ungated.** Independently of those two exits: under pre-ADR-290 code the medic slot is `anchor.index + 1`, which on this cockpit is the index `_sd2`'s live REPL occupies, and the fresh-add path would have **silently moved-with-killed that pane with no gate at all**. ADR-290 §D5 is what closed it — the slot became `anchor.index + 1 + laneCount` and `_medic` joined the park-then-place reorder list (`src/verbs/cockpit.ts:2110-2120`), so the reconcile that creates `_medic` now performs no kills and needs no `--yes`.

**The window had no identity.** `buildMedicWindowCommand` emits the claude bootstrap with **no `ATMUX_MEMBER`**, and the rotate respawn path `buildClaudeRespawnCommand` sets none either — while every team pane gets `export ATMUX_MEMBER=<name> &&` from `src/core/tui-cmd.ts::envPrefix` and every `_sdN` lane sets `ATMUX_MEMBER=sdN` inline in its ADR-279 `windows[]` command (ADR-290 §D2). A medic pane therefore could not `atmux claim` / `done` without `--as`, and its kb actor was whatever the operator typed. A reinstated member needs the same identity seam as every other pane.

## Decision

### (D1) The medic is a live cockpit member again — ADR-212 §D1 / §D5 / §D6 superseded

- **Live, not retired.** The `_medic` window is created by `atmux cockpit reconcile` from the cockpit roster's `type: "medic"` entry (ADR-279 sessions array) or the legacy top-level `medic` block, whenever `enabled: true`. This is the behaviour already in `src/verbs/cockpit.ts`; this ADR makes the documentation match the code instead of the reverse.
- **Placement.** `_medic` sits immediately after `_sd` **and** the `_sdN` lanes — slot `anchor.index + 1 + laneCount` per [ADR-290](290-superdriver-lane-shortform-and-multi-lane-cockpit.md) §D5 — and before `_superbot` and the other ADR-279 operator windows and team viewers. Desired layout: `[_sd, …_sdN lanes, _medic?, _superbot?, …other windows[], …viewers]`. The `@@mbp` target order is `_sd, _sd2, _sd3, _medic, _misc, geoyws, unum, ifca`.
- **Never pruned.** `_medic` (and the legacy `medic` / `superdoctor` spellings) stay in the never-prune guard of both the live orphan-prune pass and the dry-run planner — unchanged, restated here so no future cleanup reads the guard as retirement residue.
- **Rotated, not respawned by hand — and rotated by the operator, not by the medic.** `atmux cockpit rotate medic` remains the canonical rotation ([ADR-167](167-cockpit-rotate-verb.md) Rung C), with its four pre-flight gates intact. It is **driver-only** per [ADR-033](033-kanban-driver-only-flag.md) (`cockpitRotate` refuses with exit 78 unless `ATMUX_CALLER_SCOPE=driver`, `src/verbs/cockpit-rotate.ts:1241`), so it is not a tool the medic lane invokes on itself or on any other cockpit role; the medic raises a `kb att` row naming the wedged role and the evidence.
- **Which ADR-212 sections fall, and why.** **§D1** (retire the role at cockpit W2) — reversed by operator decision 2026-09-07; the slot is not "vacant", it is occupied and in use on `@@hax` today. **§D5** (medic retires LAST, after the Honker/orchd substrate is ≥30 days observed-stable) — its precondition was deleted by [ADR-276](276-orchd-retirement-and-atmux-scope.md) on 2026-08-27; a gate that can never open is not a sequencing plan. **§D6** (`medic-config-residue` doctor probe, yellow → red when `cockpit.json::medic` is non-null after cleanup) — never implemented, and now actively wrong: a non-null medic block is the supported configuration. No probe is added in its place. **§D2–§D4 and §D7 stand** as written: the lead-gated destructive-action pattern, the three-layer detection model, the EPIC re-fold and the context-pct enrichment are independent of who occupies the cockpit slot, and are left as the historical record of the 2026-05-21 pass.
- **ADR-077's probe substrate was never in question** and is unchanged (`src/core/doctor-class.ts`, the doctor probe registry, the probe-class taxonomy).

### (D2) Operating model — the medic is a cockpit lane, not the 2026-05-08 hourly-tick role

The medic runs in the ADR-290 §D2 lane shape, the same shape as `sd` / `sdN`:

- **Identity.** `ATMUX_MEMBER=medic` in the pane (§D3), kb actor **`claude@medic`** (or `codex@medic` when the operator runs Codex there, as on `@@hax` on 2026-09-07), lane **`medic`**.
- **Board.** It works the **`medic` kb board on `@@hax`** — addressed through the dotfiles `kb-board` / `kb-host` wrappers, never a bare local `kb`. Its own work is recorded there, not on the `superdriver` board.
- **Standing goal, operator-armed.** The operator arms the lane by hand with `/standing-goal /kb-goal` (dotfiles skills), exactly as each `_sdN` lane is armed: work the board's claimable queue in strict priority order, checkpoint expensive boundaries, sitrep at boundaries, decline out loud when nothing wise remains. atmux does not arm it and this ADR does not arm it.
- **kb rows are the only interaction surface.** Tasks, handoffs, sitreps and attention rows — no other channel. **No `tmux send-keys` into any pane** (superdriver-board rule `r-1376df29`, whose basis was verified against the live Anthropic Consumer Terms on 2026-09-02); panes are read-only for liveness checks. Anything needing the operator becomes a `kb att` row.
- **Delegate the DOING.** The medic is orchestration-plus-diagnosis; mutating work goes to isolated subagents in its own throwaway worktree. The shared cwd (`/Users/geoyws/work/src/atmux` on `@@mbp`) is **read-only** from the lane.
- **Scope.** Fleet and host health: `atmux doctor` + `atmux status --json` sweeps across enabled teams, the [ADR-198](198-medic-host-pressure-playbook.md) host-pressure playbook, structural fixes shipped as branches, cage cycles, and filing the kb rows that carry all of it.
- **Hard limits unchanged.** [ADR-077](077-superdoctor-cockpit-role.md) §D3 and `docs/medic.md` §"What it must NOT do" continue to bind verbatim: no force-push, no push to a product's staging ref, no action against any prod environment, no `--no-verify` / hook bypass, no writes into a driver or `_sd` / `_sdN` pane, no `git reset --hard` / `push --force` / `kill -9` of a non-cage process without operator clearance.

### (D3) Window command — the medic pane carries its lane identity; the superdoctor shims are removed

- **`buildMedicWindowCommand`** (`src/verbs/cockpit.ts`) returns `` `${envPrefix("medic")} ${buildClaudeWindowCommand(m)}` `` — i.e. the command now begins `export ATMUX_MEMBER=medic && ` followed by the unchanged claude invocation. `envPrefix` is the shared seam in `src/core/tui-cmd.ts` that every team pane already goes through (`tuiClaude`), so the quoting is not hand-rolled. **Measured shape:** `envPrefix` runs the name through `posixQuote`, which returns a bare word when it matches `/^[\w./@%+:=,_-]+$/` — so the literal prefix is `export ATMUX_MEMBER=medic &&`, with no single quotes, identical to the `export ATMUX_MEMBER=lead &&` that `tests/unit/core/tui-cmd.test.ts:46` pins for team panes. Recorded here because an earlier draft of this decision quoted the name.
- **Nothing else about the shape changes.** No `cd` (the medic window inherits the cockpit's cwd — see §Out of scope) and **no trailing `exec zsh -i`**: an interactive zsh prompt renders `❯`, and `cockpit rotate`'s `claudeUiGoneVerifier` treats `❯` as "claude is still up", so a trailing shell would make the post-Ctrl-C verification permanently negative.
- **`buildClaudeRespawnCommand`** (`src/verbs/cockpit-rotate.ts`) gains the same `export ATMUX_MEMBER=medic && ` prefix ahead of its existing `CLAUDE_GUARD_AGENT=1 <c-alias wrapper> …` body, so a rotated medic keeps its identity instead of coming up as an anonymous pane while the reconcile-created pane had one.
- **Shims removed.** The deprecated `buildSuperdoctorWindowCommand` export and the `buildSuperdoctorCommand` field on `ResolveTeamWindowDeps` (with its `??` fallback at the builder call site) are **deleted**. [ADR-266](266-shim-sunset-policy-and-first-sweep.md) §D2 already closed the ADR-133 shim window for every other superdoctor alias; these two were missed. Callers and test fixtures move to `buildMedicWindowCommand` / `buildMedicCommand`. Storage-layer identifiers (`superdoctor_attempts`, `SuperdoctorAttemptsRepo`, `__superdoctor__`, the `superdoctor-self-heal-escalation` dedup key) are untouched — they need a schema-migration ADR per ADR-133 §Out of scope.

### (D4) The medic has a brief — `templates/briefs/medic.md`

A brief ships at `templates/briefs/medic.md` (new, `brief-version: v1`), modelled on `templates/briefs/superdriver.md`: §0 identity check (`ATMUX_MEMBER` MUST be `medic`; `session=` MUST be the cockpit session — `atx`, or the pre-[ADR-264](264-cockpit-session-atx-rename.md) `atmux_cockpit` still live on `@@hax`; `window=` MUST be `_medic`), then who you are, the §D2 operating model, what you may do, the ADR-077 §D3 / `docs/medic.md` hard limits, the reporting rules, and a `## Standing Goal` section carrying the goal body the operator arms. On identity mismatch the medic **STOPs and raises a kb attention row** — there is no lead to `atmux send`: the cockpit tier's windows are `_sd`, the `_sdN` lanes, `_medic`, `_superbot`, operator windows and viewers ([ADR-290](290-superdriver-lane-shortform-and-multi-lane-cockpit.md) §D5), none of which is a team-lead, and the superdriver lanes already escalate through kb rows for the same reason ([ADR-290](290-superdriver-lane-shortform-and-multi-lane-cockpit.md) §D2).

### (D5) "Retired roles" wording drops medic everywhere it reads as current guidance

Every brief §0 clause of the form `**Retired roles** (sentinel ADR-211, medic ADR-212, jury ADR-213, ombudsman ADR-214)` drops medic and adds `medic` to the **Cockpit-tier roles** list, which becomes `superdriver, medic, enforcer, discorder, merger, unblocker`. The same sweep applies to `docs/medic.md`, `docs/PRD.md`, `docs/ARCHITECTURE.md`, `docs/RUNBOOK-cockpit.md`, `README.md`, `CHANGELOG.md`, `src/verbs/help.ts`, `src/verbs/README.md` and the bundled skills under `plugins/atmux/skills/` (`cockpit-rebuild`, `sweep`, `team`, `bau`, `heads-up`, `session`, `whip`). Sentinel stays retired per ADR-211; jury stays retired per ADR-213; ombudsman is untouched (see §Out of scope). Narrative *inside* ADR bodies is left alone — an ADR records what was decided when, and is amended, never rewritten. `templates/briefs/lead.md` keeps its `## Rotation signals` section: the title and item 9 are retitled to read as history ("retired per ADR-212, reinstated per ADR-291"), because the lead-gated rotation signals themselves still ship.

## Consequences

- **Change set (one commit family).** This ADR + `docs/adr/INDEX.md` row + append-only amendments on ADR-212 / ADR-077 / ADR-290; `src/verbs/cockpit.ts` (`envPrefix` prefix, `buildSuperdoctorWindowCommand` and `buildSuperdoctorCommand` deleted, doc comments), `src/verbs/cockpit-rotate.ts` (same prefix + doc comment), `src/verbs/help.ts` + `src/verbs/README.md` (rotate text); `templates/briefs/medic.md` (new) + the twelve briefs carrying the retired-roles clause; `docs/medic.md`, `docs/PRD.md`, `docs/ARCHITECTURE.md`, `docs/RUNBOOK-cockpit.md`, `README.md`, `CHANGELOG.md`; the bundled skills listed in §D5; `tests/unit/verbs/cockpit.test.ts` + `tests/unit/verbs/cockpit-rotate.test.ts`.
- **The `@@mbp` cockpit gains a window on the next reconcile.** With ADR-290 §D5's slot fix already on this branch, `atmux cockpit reconcile` creates `_medic` at index 4 and reorders by moves only — no kills, no `--yes`, `_sd2` / `_sd3` REPLs untouched. Running that reconcile is an **operator step**; this ADR does not touch the live cockpit.
- **The `@@hax` cockpit is already correct** — its `_medic` window (window 2, running codex) predates this ADR and keeps running. Its window will move behind any `_sdN` lanes the operator later declares there.
- **A rotated medic and a freshly reconciled medic now carry the same identity.** Before this ADR the two paths disagreed (neither set `ATMUX_MEMBER`, but only the reconcile path was documented as the canonical shape).
- **Two exported symbols disappear.** Anything importing `buildSuperdoctorWindowCommand` or injecting `buildSuperdoctorCommand` breaks at typecheck rather than silently — intended, and the in-tree callers move in the same commit.
- **No schema change.** `type: "medic"` / the top-level `medic` block / `enabled` / `autoStart` / `claudeAccount` / `tuiOverrides` are all as shipped.
- **The `medic-config-residue` probe will never exist.** Anything expecting it (nothing in tree on 2026-09-07) should expect nothing.
