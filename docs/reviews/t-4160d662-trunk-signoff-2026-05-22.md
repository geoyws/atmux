## ADR-224 §D2 incremental-mode auto-rename (`atmux start`)

`src/core/orchd-window.ts:94-130` (T3, 527a1fc):

- Legacy probe: `LEGACY_RELAYD_WINDOW = "__relayd__"` (const, un-exported — only ref to the legacy literal in code post-rename).
- Single `listWindows(session)` call covers BOTH the rename probe AND the spawn-idempotence check.
- Detected → `tmux rename-window` in-place (no kill, no respawn — supervisor PID + pane state + log handles + child Rust binary all survive).
- `return false` after successful rename → skip-respawn (prevents racing a fresh supervisor against the renamed one).
- Defensive: rename-throws → warn + fall-through to idempotence check; listWindows-throws → warn + spawn-attempt (preserves existing degrade-gracefully shape).
- Idempotent: re-running on already-renamed cage finds no `__relayd__` → no-op.

T3 commit reports 91% line coverage on orchd-window.ts; my probe confirms **100% line / 100% func** coverage (the rename probe + spawn-idempotence paths are all exercised by `tests/unit/core/orchd-window-rename.test.ts` (6 tests / 21 expects) + `tests/unit/core/orchd-window.test.ts`). ✅
