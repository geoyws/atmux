# Release notes

Per-day append-only progress timeline per [ADR-147](../adr/147-ombudsman-and-release-notes.md) §D4 "Discovery".

## Layout

```
docs/release-notes/
├── README.md            ← this file (the entry-point per ADR-147 §D4)
└── <YYYY>/              ← year folder
    └── <MM>/            ← month folder
        ├── 2026-05-15.md
        ├── 2026-05-16.md
        └── …
```

- **One file per day.** File path is `docs/release-notes/<YYYY>/<MM>/<YYYY>-<MM>-<DD>.md` (e.g. `docs/release-notes/2026/05/2026-05-15.md`).
- **Year + month folders** for navigability: `ls docs/release-notes/2026/05/` gives a month-at-a-glance view. No per-day folders — the day-file IS the unit (ADR-147 §D4 tradeoff: 365 dirs/year × multiple files/day = explosion, so we stay with one file per day with append-only sections).
- **Append-only sections** per skeleton — no destructive overwrites; race writes happen at the section level and are conflict-free as long as each agent appends only to its own section.

## File skeleton

Every day-file follows the same skeleton (auto-created by the first writer of the day):

```markdown
# <YYYY>-<MM>-<DD>

## Shipped (kanban→done)

(appended by committer post-fan-in, or hygiene-tick backstop)

## Merges (branch→trunk)

(appended by committer post-trunk-merge per ADR-145 + ADR-146)

## ADRs landed

(appended by hygiene-tick on detecting new docs/adr/*.md, OR by ADR author)

## Complaints adjudicated

(appended by ombudsman per ADR-147 §D3)

## Doctor regressions (optional)

(appended by medic on red-row escalation; empty most days)

## Notes (optional)

(operator-curated narrative; empty most days)
```

## Section ownership

Each section is owned by a specific agent — multiple agents append to the same day-file safely because each writes only to its own section (per ADR-147 §D4 + §D6).

| Section                       | Owner                  | When appended                                                        |
|-------------------------------|------------------------|----------------------------------------------------------------------|
| `## Shipped (kanban→done)`    | committer                 | post-fan-in (ADR-147 §D4); hygiene-tick is the backstop              |
| `## Merges (branch→trunk)`    | committer                 | post-trunk-merge per ADR-145 + ADR-146                               |
| `## ADRs landed`              | hygiene-tick / author  | hygiene-tick on detecting new `docs/adr/*.md`; ADR author on commit  |
| `## Complaints adjudicated`   | ombudsman              | per adjudication (ADR-147 §D3)                                       |
| `## Doctor regressions`       | medic                  | on red-row escalation (optional; empty most days)                    |
| `## Notes`                    | operator               | curated narrative (optional; empty most days)                        |

## Multi-team monorepos (forward-compat, ADR-090 epic-team scope)

For projects with multiple teams writing to the same repo (per ADR-090 epic-team), all teams write to **the same physical day-file** at the repo root. Each team appends only to its `### <team>` sub-section within `## Complaints adjudicated` (and any other team-segmented section). For atmux today (single team `atmux`), this is N/A — there's only one team writing, so no sub-section prefix is needed.

## How to browse

- **Today's progress**: `cat docs/release-notes/$(TZ='Asia/Kuala_Lumpur' date +%Y/%m/%Y-%m-%d).md` (returns 1 file).
- **This month**: `ls docs/release-notes/$(TZ='Asia/Kuala_Lumpur' date +%Y/%m)/`.
- **Search across days**: `rg "ADR-147" docs/release-notes/` returns chronological hits.
- **30-day TOC**: auto-generated by hygiene-tick or `atmux release-notes index` (verb shipped under ADR-147 T1 follow-up). Until that lands, `ls -t docs/release-notes/<Y>/<M>/` works.

## Auto-create + idempotency

The first writer of the day to `docs/release-notes/<Y>/<M>/<Y-M-D>.md` creates the file with all skeleton sections empty. Subsequent writers append to their own section only. No locking needed — section headers act as natural insertion anchors. Race writes happen at most under a few hundred ms and are append-only (no destructive overlap), per ADR-147 §D4.

## Doctor backstop

A doctor probe `release-note-missing` (warn-class, NOT block) per ADR-147 §D5 fires when:

- Today's date has ≥1 commit on trunk (verified by `git log --since "today 00:00 MYT"`), AND
- `docs/release-notes/<Y>/<M>/<Y-M-D>.md` does not exist.

This is a backstop for missed days. The expected pattern is committer (or hygiene-tick) auto-creates the file on the first event of the day. The probe surfaces missed days for ombudsman or hygiene-tick to backfill.

## Doc-discipline interaction

Per [ADR-147](../adr/147-ombudsman-and-release-notes.md) §D7: release notes are a **documented surface** for the purposes of `CLAUDE.md` §"Same-commit doc updates" discipline. New ADRs that introduce a new release-notes section (e.g. a future `## Security incidents`) MUST include the same-commit update to this README documenting the section. Reviewer enforces.

Ombudsman appending entries to existing sections is NOT subject to same-commit doc-update — that IS the doc update.
